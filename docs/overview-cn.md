# Sieve — AI / Agent 信源治理与渗透痕迹检测

在你自己的家庭网 / 公司内网里，检测 **AI 与 agent 的异常流量痕迹**：影子 AI 外泄、
脚本化抓取、自主 agent 回连、DoH 绕过。从最小做起，逐层验证，最终合并成统一研判。

> 定位：**异常行为检测**，不是"AI 内容审查"（路由器位置只有元数据，无 MITM 就看不到内容）。
> 仅用于你拥有或已获授权的网络。

## 最快上手（Mac 上无需任何基础设施）

```bash
python3 sieve-s0/sieve_s0.py --demo       # DNS 层
python3 sieve-s2/sieve_s2.py --demo       # TLS 指纹层
python3 sieve-verify/evaluate.py          # 准确率评估（含误报陷阱）
python3 sieve-s3/sieve_s3.py --demo       # 合并研判
```

全部纯 Python 标准库，无需 `pip install`。

## 架构

```
采集                打分                    合并           告警
┌─────────┐   ┌──────────────────┐
│ Pi-hole │──▶│ S0  DNS 侧信号     │─┐
└─────────┘   └──────────────────┘  │   ┌──────────┐    ┌──────────┐
                                     ├──▶│ S3 研判   │───▶│ Telegram │
┌─────────┐   ┌──────────────────┐  │   └──────────┘    └──────────┘
│Zeek+JA4 │──▶│ S2  TLS 侧信号     │─┘        ▲
└─────────┘   └──────────────────┘           │
                          sieve-verify 用真实数据持续复测、反馈调参
```

**分工**：S0 看"连了谁"（DNS），S2 看"谁在连、怎么连"（TLS 指纹 + 连接）。
同一设备两层同时命中 = 高置信。

## 关键设计结论（都是验证量出来的）

1. **纯 DNS 会冤枉人**：开发者浏览器用 ChatGPT 被 DNS 层误判（F1 0.75）。
2. **TLS 指纹修好它**：JA4 区分脚本/浏览器，S2 精确率 100%。
3. **两层缺一不可**：纯 DoH 绕过无 LLM 域名，靠 S2 的脚本指纹才抓到。
4. **合并 ≠ 相加**：S3 用"S2 主判 + ≥2 信号族 + 人类护栏"，在 golden 集上 **FP=0 FN=0**。

诚实边界：`curl_cffi` 等能伪造浏览器 JA4 → 抓得住图省事的脚本，抓不住刻意伪装的；
DoH/ECH 在收窄视野，须在防火墙封 DoH、强制 DNS 收回。详见手册。

## 真实部署顺序

1. 路由器 DHCP 把 DNS 指向 Pi-hole → 跑 `sieve-s0 --observe` 两周建基线。
2. 交换机 SPAN 口 + 树莓派跑 Zeek（装 `zeek/ja4` 包）→ 跑 `sieve-s2 --observe`。
3. 按 `agent-trace-playbook.html` 的 T1–T7 在自己网里自测，用 `sieve-verify` 量误报/漏报、调参。
4. 两层就位后用 `sieve-s3 --alert` 统一告警；S0/S2 只留 observe 供排查。

每个 Stage 都能独立交付，不必等全套建成。
