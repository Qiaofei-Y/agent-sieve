授权边界。本手册所有"攻击"动作都只在你自己拥有或已获书面授权的网络上，对你自己的设备执行，目的是验证检测能力。切勿对第三方网络、他人设备或未授权目标使用其中任何一步。
01

先把"AI 入侵"拆成三个威胁模型

三者在网络层的可检测性天差地别，混为一谈会让你既抓不到真的、又误报一片。

A

外部 AI 爬虫扒你的服务

GPTBot / ClaudeBot / PerplexityBot 等抓取你暴露在公网的 NAS、博客、反代。也包括假冒爬虫——UA 写着 GPTBot，IP 却不在官方段里。

难度 · 容易
B

影子 AI 外泄

内网某设备 / 某人把数据持续喂给 LLM API（api.openai.com 等），或本地跑的 agent 在外发内容。你最该先解决的一类。

难度 · 中
C

自主 agent / AI 驱动入侵

电线上它和普通脚本入侵几乎一样——AI 在攻击者云端，过来的只是请求。出卖它的是"机器节奏"，不是"AI"本身。别过度宣称。

难度 · 难
02

四个观测点，各自看得到什么

在路由器这个位置你只有元数据。按部署成本从低到高排列，颜色在后面的测试矩阵里复用。

DNS

Pi-hole / AdGuard Home

成本 · 极低

当全网 DNS，记录每台设备每一次域名查询。抓威胁 B 和用系统 DNS 的本地 agent 最快的办法。

  • 匹配已知 LLM API / agent 域名清单
  • 发现从未见过的新域名（shadow source）
能看到查询的域名、哪台设备、频率
看不到走 DoH/DoT 的客户端（直接绕过）
FLOW

路由器连接日志 / conntrack

成本 · 低

每条连接的 IP:端口、字节数、时间戳。即便 DNS 被绕过，IP 层仍然留痕——按 IP 反查 LLM 厂商归属。

  • 定时回连（beaconing）的规律间隔
  • 异常外发体量 / 整站遍历
能看到对端 IP、流量大小、节奏
看不到具体内容、具体 URL
TLS

镜像口 + Zeek（JA4 指纹）

成本 · 中

交换机 SPAN 口把流量镜像给一块树莓派跑 Zeek，提取 TLS 握手的 JA4 指纹——它由网络栈决定，不受伪造 UA 影响。

  • python/Go/curl 的指纹 ≠ 真浏览器
  • SNI（除非对端启用 ECH）、证书、QUIC
能看到客户端是不是脚本、连的域名
看不到被 curl_cffi 伪造的浏览器指纹
HOST

端点 · OpenSnitch / Little Snitch

成本 · 中（需装）

装得上端点的话，这是唯一能把流量落到进程的观测点——是哪个二进制、哪个脚本在外连。

  • 进程级出站白名单 / 告警
  • 解密前的内容（本机可见）
能看到进程、命令行、完整目的地
看不到装不了端点的设备（IoT、访客机）
03

两条必须先接受的物理边界

不认清这两点，后面所有检测都是自欺。

① 没有 MITM 就只有元数据

流量是 TLS 加密的。不在每台设备装你的根证书做中间人解密，你永远看不到"读了哪个页面、发了什么内容"。家用场景不建议全网 MITM（破坏性大、风险高），所以把产品定位成"异常行为检测"，不是"内容审查"。

② DoH/DoT 和 ECH 正在收紧视野

  • DoH/DoT：客户端自带加密 DNS 会直接绕过 Pi-hole。这是头号敌人——必须在防火墙封掉 853 端口、拦截已知 DoH 解析器域名，把 DNS 强制收回到你手里，否则 DNS 这层形同虚设。
  • ECH（RFC 9849，2026-03 定稿）会加密 SNI，连域名都看不到。目前服务端几乎只有 Cloudflare 上线，大部分站点 SNI 仍可见——但这是单向趋势，别把架构押在 SNI 可见上。
  • 指纹可伪造：curl_cffi --impersonate chrome / tls-client 能复刻浏览器 JA4。所以 JA4 抓得住图省事的 agent，抓不住刻意伪装的——它是信号之一，不是终判。
04

从最小做起：四阶段落地

每个阶段都能独立交付价值，不必等全套建成。

S0
一个下午

Pi-hole 当全网 DNS + 域名清单

路由器 DHCP 把 DNS 指向 Pi-hole，查询日志里匹配约 40 个已知 LLM API / agent 域名。零额外硬件（树莓派或一台闲置机即可）。

✓ 威胁 B · 影子 AI✓ 本地 agent（系统 DNS） 
# 从 Pi-hole 查询日志里捞 LLM / agent 流量（最小可用）
sqlite3 /etc/pihole/pihole-FTL.db \
  "SELECT datetime(timestamp,'unixepoch','localtime') t,
          client, domain
   FROM queries
   WHERE domain LIKE '%openai.com'
      OR domain LIKE '%anthropic.com'
      OR domain LIKE '%generativelanguage.googleapis%'
      OR domain LIKE '%api.perplexity.ai'
   ORDER BY timestamp DESC LIMIT 50;"
S1
一天

对暴露的服务核验爬虫真伪

对你公网可达的反代 / NAS 访问日志，拉厂商官方 IP 段 JSON 做正向核验——UA 声称是 GPTBot，但源 IP 不在 openai.com/gptbot.json 里，就是冒充。

✓ 威胁 A · 真假爬虫 
# 官方 IP 段 JSON（定时拉取，勿硬编码）
openai     → https://openai.com/gptbot.json
anthropic  → https://claude.com/crawling/bots.json
perplexity → https://www.perplexity.ai/perplexitybot.json

# 现成开源工具：按日更新的 IP 段 + 核验脚本
github.com/ramhee98/ai-crawler-ipranges
github.com/ayronjins/ai-crawler-verify
S2
一个周末

镜像口 + Zeek：抓脚本客户端和回连

有网管交换机就开 SPAN 口，没有就用支持镜像的软路由，把流量喂给树莓派上的 Zeek。从 ssl.log 取 JA4，从 conn.log 算回连节奏。

✓ 威胁 C 的可检测部分✓ 脚本 vs 浏览器 
# Zeek 起监听（Zeek 5.2+ 原生支持 QUIC）
zeek -i eth0 LogAscii::use_json=T

# 从 ssl.log 里找非浏览器 JA4（python/go/curl 的指纹库比对）
jq -r 'select(.ja4 != null) | [.ts,.server_name,.ja4] | @tsv' ssl.log

增量

DNS / FLOW / TLS 三源按设备聚合，套下面的评分规则，超阈值推告警（Telegram / 邮件）。这一步才像个产品。

单条信号都会误报。按设备在时间窗内累加权重，超阈值才告警，压住噪声。

建议阈值：家庭网 ≥ 50 推通知、≥ 80 需人工查看；公司内网按设备基线调整。先跑两周纯观察模式建立每台设备的正常画像，再开告警——否则第一周会被自己的正常流量淹没。

07

公司内网的三点不同

  • 观测点更好拿：有 MDM 就能全网铺端点(HOST)，有网管交换机就有现成 SPAN 口，这是家庭网没有的优势。
  • 基线更重要：员工本来就在用一堆 SaaS，LLM 域名命中率天然高。重点从"有没有"转向"哪台设备异常地多、哪个账号在非工作时间批量外发"。
  • 合规先行：员工流量监控涉及隐私与劳动法。部署前先过内部政策与知情同意，别把技术方案直接当成可落地方案。
