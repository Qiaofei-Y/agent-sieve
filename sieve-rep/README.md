# Sieve Reputation — 跨租户信誉库（护城河）

**简体中文** · [English](README.en.md)

> 单个装机点只看到局部。把各装机点**本地判为可疑的公共指标**（公共 LLM/爬虫域名、
> JA4 指纹）按**跨租户去重计数**汇总成一份信誉源，每个点再消费它——"一处标坏、处处预警"。
> 越多人用越准，这是网络效应护城河。
>
> **纯 Python 标准库。隐私优先、自愿参与、抗投毒。**

配套：被 [`../sieve-s3/`](../sieve-s3/) 作为**可选附加信号**消费（无信誉源时行为与之前完全一致）。

---

## 为什么这是护城河

代码两周能被抄走，1000 个装机点一年里跨租户确认过的"坏域名 + 坏指纹"抄不走。
价值随贡献者数量增长，后来者难以追赶——这正是 Sieve 真正值钱的地方，而不是检测代码本身。

## 三个工具 + 一个数据流

```
各装机点                     聚合端                    各装机点
contribute.py  ──reports──▶  aggregate.py  ──feed──▶  sieve-s3 消费
(隐私过滤导出)              (跨租户去重计数)          (附加信誉信号)
```

- **`contribute.py`** — 把本地已判可疑、且属**公共类别**的指标导出成观测报告。
- **`aggregate.py`** — 把多份报告按**不同租户数**聚合成信誉源（`feed.json`）。
- **`reputation.py`** — 引擎：feed 读写/完整性校验/查询/聚合，被上面两个和 sieve-s3 复用。

## 30 秒看效果（Mac 上即可跑）

```bash
python3 contribute.py --demo     # 看隐私过滤：内网域名被丢弃，只导出公共指标
python3 aggregate.py  --demo     # 看网络效应 + 抗投毒：同一域名被 N 个租户举报才转 bad
python3 selftest.py              # 回归自测
# S3 消费信誉源（demo 会自动加载 feed.example.json）：
python3 ../sieve-s3/sieve_s3.py --demo    # 命中设备多出一条 "REP 跨租户信誉命中"
```

## 隐私模型（可信度的关键）

- **只导出可疑指标本身**（域名 / JA4），**绝不导出**：内网域名、IP、设备标识、具体时间点、
  浏览历史、任何正常流量。
- **白名单式类别过滤**：只有公共类别（`llm_api / agent_infra / content_farm / scraper /
  doh_resolver / ja4_script`）才允许导出；任何不在此列的（尤其是内网域名）一律丢弃——
  贡献端和聚合端**双重拦截**。
- **自愿**：`contribute.py` 只在你主动运行时导出。
- **假名**：`tenant_id` 是本机随机生成的假名（存 `.tenant_id`，不入库、不含可识别信息），
  仅用于聚合端去重。
- 时间粒度到**月**，不含具体时间点。

## 抗投毒

- 信誉强度 = 举报的**不同租户数**；同一租户对同一指标**只计一次**——单个投毒者刷 100 次也只算 1 票。
- 单租户单次贡献量封顶（`max_per_tenant`）。
- 达到 `confirm_min_tenants`（默认 3）个不同租户才标 `bad`，否则停留 `suspicious`（不触发 S3 信誉信号）。

## 完整性与分发

- `feed.json` 带内容 `sha256` 校验，消费端加载时自动核对，被篡改会告警。
- **生产环境应再对 feed 做 GPG 签名**后分发（像威胁情报订阅源那样）——校验哈希防意外损坏，
  签名防中间人替换。当前原型只做哈希校验。

## S3 怎么消费

sieve-s3 配置 `reputation_feed` 后，会对每台设备看到的域名/JA4 查信誉源；命中**跨租户确认为 bad**
的指标就附加一个独立的 `rep` 信号族（默认 +30）并标 `[REP]`、置信=高。它是**纯附加**：
只会增强判定、提升置信，不会抑制原有逻辑，因此不会制造新漏报；无信誉源时 S3 行为不变。

## 文件

| 文件 | 作用 |
|---|---|
| `reputation.py` | 引擎（feed 读写/校验/查询/聚合），被 contribute/aggregate/sieve-s3 复用 |
| `contribute.py` | 贡献端：隐私优先导出观测报告 |
| `aggregate.py` | 聚合端：跨租户去重并成信誉源 |
| `feed.example.json` | 示例信誉源（带有效完整性哈希） |
| `config.example.json` | 消费端配置模板 |
| `selftest.py` | 回归自测（隐私/去重/投毒/完整性/查询） |
| `.tenant_id` / `feed.json` / `reports/` | 运行时生成，不入库 |
